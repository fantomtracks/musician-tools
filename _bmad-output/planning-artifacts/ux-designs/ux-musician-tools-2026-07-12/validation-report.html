Musician Tools — Catalog — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-musician-tools-2026-07-12/{DESIGN.md, EXPERIENCE.md}

The spine pair is a strong, ship-ready contract: a consumer (architecture / story-dev) can source-extract cleanly, every {path.to.token} reference resolves, and the load-bearing decisions (order of Browse, inline-Add, calm-duplicate, snapshot invariant, 403-not-404, gradient tiles) are committed with DL-/FR- citations. The inheritance discipline is exemplary — no re-declared hex, all new surfaces map to concrete existing Tailwind classes verified to exist in src/index.css. Two gaps were worth closing before stories, and both were addressed in this finalize pass: read-surface error / deleted-fiche-404 states (the spine leans hard on Epic-18 deep-linking but never said what a shared link to a deleted /catalog/:uid renders), and the brand-gradient tile contrast, which was asserted but not quantified — the light-mode brand-500 end measures ≈4.27:1 against white, under AA for the small counter.

Accessibility lens. The pair inherits a solid a11y floor and handles the headline risks well (duplicate state is icon + text not color-alone, icon-only Add carries a full aria-label, the swipe-only rail trap is defused, the import recap is aria-live). What the new Catalog surfaces left open were SPA/dynamic-content concerns the floor never faced: clickable card/row bodies nesting interactive Add buttons, no focus restore on back-navigation from the detail route, un-announced search-to-collapse / no-results updates, and a gradient tile committing text-white with no numeric target. None were full blockers, but several were high because downstream code mirrors this spine verbatim — they have been encoded into the Component Patterns, State Patterns, Accessibility Floor and DESIGN Colors/Components in this pass.

Accessibility review (WCAG 2.1 AA)

review-accessibility.md

The spine pair inherits a solid a11y floor and handles the headline risks well: the duplicate state is icon + text (not color alone), icon-only Add buttons get a full aria-label, the swipe-only rail trap is defused with a focusable container, and the Collection-import recap is aria-live. What the new Catalog surfaces left open are mostly SPA/dynamic-content concerns the floor never had to face: focus is not restored on back-navigation from the detail route, the search-to-collapse + no-results updates are not announced to screen readers, the clickable card/row bodies nest interactive Add buttons/badges inside a clickable region, and the gradient tile commits text-white without a numeric contrast target. None are full blockers, but several are high because downstream code will mirror this spine verbatim. The four highs and three of the mediums were applied in this pass; the remaining mediums/lows (ConfirmDialog return-focus + dialog semantics, curator-form error ARIA, snap-scroll focus affordance, 403 focus management, card-fallback list semantics) are documented for story-dev.

high applied

Nested interactive controls in clickable card/row body

EXPERIENCE lines 82-83; DESIGN Components 61-62, 67-68
The clickable card/row body (→ detail route) contains an inline Add button and, in the duplicate case, a clickable ✓ Already in your songlist badge. A <button>/<a> inside a clickable <a> is invalid HTML and breaks keyboard/SR activation (ambiguous target, focus-order noise).
Fix: Committed the stretched-title-link pattern in DESIGN Components + a Do/Don't and in EXPERIENCE Component Patterns + Accessibility Floor: the title is the navigation <a>; Add button and duplicate badge are siblings raised above it (relative z-*), independent tab stops — never descendants of the link.
high applied

Focus not restored on back-navigation

EXPERIENCE lines 46, 110 (DL-10)
Back-nav from /catalog/:uid restores scroll position + filters but not keyboard focus. On a data-router SPA, history.back() leaves focus on <body>, so keyboard/SR users lose their place in the list.
Fix: Added to Accessibility Floor + Interaction Primitives: persist the activating element's id/ref in history/router state and move focus back to the originating row/card on return to Browse.
high applied

Search-to-collapse / no-results not announced

EXPERIENCE lines 80, 95 (WCAG 4.1.3)
Search-to-collapse, live list filtering, and the no-results state are not announced to screen readers — no aria-live/status region on the results list or a result count. A sighted user sees rails vanish and the list shrink; a SR user hears nothing.
Fix: Wrapped the filterable list in aria-live="polite" announcing the result count (and no-results); the collapse is a non-silent, focus-safe DOM change (collapse happens while focus is in the search field). Encoded in Accessibility Floor + relevant State/Component Pattern rows.
high applied

Gradient tile commits text-white with no numeric target

DESIGN.md line 37 / token collection_tile_gradient
White text on the brand→purple gradient tile states no numeric target, and a gradient means contrast varies across the tile. The count is meta-sized small text (needs ≥4.5:1); white over the lightest stop (brand-500, a mid-tone) is the failure risk in both light and dark variants.
Fix: Committed explicit targets (name ≥3:1 if ≥18.66px bold else ≥4.5:1; count ≥4.5:1) and added a bottom scrim token (components.collection_card_scrim, from-black/40) behind the text, verified against the lightest stop in both themes.
medium applied

Floor line 122 vs DESIGN lines 72, 74

Fix: Reconciled once in Accessibility Floor — the icon-only + and the clickable "Already in your songlist" badge keep a ≥44×44px hit area (min-h/min-w or padding), no silent shrink in tight cells; contradiction removed in DESIGN Add-button spec.
