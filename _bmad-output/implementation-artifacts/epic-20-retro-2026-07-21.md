## 🔎 Défis & leçons

1. **🎭 La QA visuelle a ENCORE révélé un vrai gap UX après review verte — 3ᵉ épic de suite (18/19/20). LEÇON PRIORITAIRE.**
   Le récap d'import (toast bas d'écran + « Added 0 » au ré-import) était trop discret et confus. La review 3 couches l'avait relevé (Low) mais dismissé comme « conforme au wording de l'AC ». northwood l'a senti en 10 s en usage réel → corrigé en suivi (bandeau inline persistant + copy par segments).
   **Leçon : un dismiss « conforme-à-l'AC-verbatim » sur un finding de *feedback utilisateur* est dangereux — le wording de l'AC lui-même peut être le point faible. Pour les flux de feedback user-facing, pondérer plus haut les Low « clarté/visibilité », ou defer-with-note plutôt que dismiss.**
2. **🐛 Mocks de service partiels fragiles.** Ajouter `listCollections` (rail) a cassé `Catalog.test.tsx` : son mock remplaçait tout l'objet `catalogService` sans la méthode. Même classe en 20-2 (mocks partiels masquent les régressions de signature — relevé par la review).
   **Leçon : quand un composant gagne un appel service, grep les suites qui mockent ce service et ajouter la méthode ; envisager une *factory de mock partagée* pour `catalogService` pour éviter la dérive par fichier.**
3. **🧭 Best-effort non-atomique (20-3) : design volontaire qui « sent mauvais » aux reviewers.** Les 3 couches ont flaggé l'absence de transaction / de abort. Ancré par commentaires code + story → l'Auditor a clos sans re-litiger.
   **Leçon : quand un design viole exprès une best-practice (pas de transaction englobante), l'ancrer dans le code ET la story pour que le triage ne re-litige pas (ça a marché).**
4. **🩹 Papercuts UX qui ne sortent qu'avec des données réelles.** Collection à 0 fiche = tuile cul-de-sac (membres tous-brouillon → `songCount` 0 pour non-curateur), « Added 0 »… invisibles pour 474 tests verts. Attrapés par patch review (filtre `songCount>0`) + QA navigateur.
   **Leçon : seeder des données réalistes + cliquer le vrai parcours pour toute story user-facing ; le navigateur attrape ce que les tests mockés n'attrapent pas.**
5. **🔁 Feedback des actions idempotentes.** Le ré-import était *correct* (skip + playlist réutilisée, aucun doublon) mais le feedback « rien de neuf » n'était qu'une version dégradée du message de succès (« Added 0 · … »).
   **Leçon : une action idempotente/no-op mérite son PROPRE message clair (« 3 already in your songlist »), pas un « Added 0 » dégradé.**
