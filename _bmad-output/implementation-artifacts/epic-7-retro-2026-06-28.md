1. **Cadrage en amont tenu** — un epic sécu de 13 stories avec un design app-wide écrit *avant* de coder. Le pattern contrôleur (ownership par scope → 404, anti-oracle) a été appliqué uniformément. La leçon d'Epic 8 (« cadrer avant de coder ») a été appliquée.

3. **Course-correction assumée en plein vol** — soft-gate → hard-gate tranché et exécuté proprement, en résolvant un résidu existant plutôt qu'en l'empilant.
4. **Test manuel global + correctifs sur la branche avant merge** — le rituel a tenu sur un epic à fort risque (auth exposée sur Internet).

## Ce qui a fait mal / angles morts

1. **Clé Resend prod désynchronisée** — pendant l'epic, la prod a tourné un temps avec l'ancienne clé API Resend (mauvaise *team*). **Résolu** (clé rotée en prod, confirmé 2026-06-28). Pour un epic compte+email, c'est le maillon qui pouvait casser silencieusement en prod.
2. **Pas de staging — migration prod à l'aveugle (7.2)** — bien passée, mais reste le risque structurel n°1 pour tout epic futur touchant le schéma.
3. **UX des lock-outs anti-oracle confuse** — 429 detail-free au login (choix 7.4 assumé), mais un vrai user rate-limité ne comprend pas pourquoi il est bloqué. Dette UX latente.
4. **Code review *après* merge en prod (v1.6.0)** — les 5 correctifs du 2026-06-28 sont bons mais corrigent du code déjà déployé. Une review avant merge aurait mordu plus tôt.
