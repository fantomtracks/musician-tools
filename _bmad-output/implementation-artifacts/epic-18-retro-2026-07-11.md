## 🔁 Lessons
1. **StrictMode était l'éléphant — et le harnais de test ne le reproduisait pas.** `main.tsx` monte sous `<StrictMode>` (double montage en dev, force les effets idempotents), mais `renderSongs` tournait **sans**. Résultat : **3 des bugs trouvés à la main étaient StrictMode-only** — (a) `isMountedRef` posé en cleanup-only restait `false` → « already exists » sur n'importe quel titre ; (b) deep-link double-invoke ; (c) double-popup à la suppression. Suite **verte**, dev cassé. → **Action A** : `renderSongs` en StrictMode **par défaut**.
2. **L'égalité par sérialisation exacte est fragile face aux données serveur.** `isFreshSong` faisait `JSON.stringify(form) === JSON.stringify(initialSong)` ; ça cassait dès que le form était reconstruit depuis l'objet serveur (métadonnées + `null` vs `''`). Le « fresh silent delete » ne marchait **jamais** en vrai ; le mock minimal le masquait. → **corrigé** (comparaison de contenu) + **Action B** : fixtures au format serveur (`makeSong`).
3. **Un correctif de review a lui-même introduit un bug.** Le fix #2 (stale-location) a posé le `isMountedRef` cleanup-only → le bug StrictMode #1. La review adversariale est nécessaire mais **pas suffisante** pour le cycle-de-vie ; la QA manuelle dans le vrai runtime reste la dernière ligne. C'est northwood qui a pris les 3 derniers.
4. **La densité de bugs = le terrain, pas la rigueur.** Cet epic a touché le cycle-de-vie React (router, refs, effets, transitions) — la zone la plus glissante du projet, contrairement aux epics back/logique habituels. Le pic de bugs était attendu ; les deux angles morts (StrictMode, mocks minimaux) l'ont amplifié.
